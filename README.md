# Cinema REST API

## Описание
Серверная часть системы управления кинотеатром. Предоставляет REST API для управления залами, жанрами, фильмами, расписанием сеансов, пользователями и продажей билетов. Данные хранятся в PostgreSQL, доступ к ним реализован через Spring Data JPA.

## Функциональность
* **Полный CRUD** для залов, жанров, фильмов, сеансов и пользователей.
* **Автоматическая генерация билетов**: при создании сеанса система создаёт билет на каждое место зала.
* **Фильтрация**: фильмы по названию и/или жанру, сеансы по залу, билеты по сеансу, статусу и покупателю, пользователи по роли.
* **Бизнес-правила**:
  - Запрещено удалять зал или фильм, у которых есть сеансы, и жанр, который используется в фильмах.
  - Запрещено менять схему мест зала (ряды и места), если для него существуют сеансы.
  - Запрещено удалять сеанс с проданными билетами и менять фильм сеанса, если билеты уже проданы. Базовая цена обновляется только у ещё не проданных билетов.
  - Сеансы в одном зале не могут пересекаться по времени (с учётом длительности фильма).
  - Билет нельзя продать дважды; удалять можно только свободные билеты.
  - Нельзя удалить пользователя, у которого есть купленные билеты.
* **Ролевая модель**: роли `ADMIN`, `MANAGER`, `CUSTOMER` (абстрактный класс `User` и наследники `AdminUser`, `ManagerUser`, `CustomerUser`).
* **Отчёты**: выручка сеанса, число проданных билетов по фильмам, общая статистика.
* **Проверка входных данных**: входные DTO валидируются (`@Valid`), пароль пользователя не возвращается в ответах API.

## Структура проекта

Код разделён на пакеты `com.cinema.*`:

| Пакет | Назначение | Ключевые классы |
| :--- | :--- | :--- |
| **`model`** | JPA-сущности, соответствующие таблицам БД, и перечисления. Используют Lombok (`@Getter`, `@Setter`). | `Hall`, `Genre`, `Film`, `FilmSession`, `Ticket`, `User` (абстрактный), `AdminUser`, `ManagerUser`, `CustomerUser`, `UserRole`, `TicketStatus` |
| **`repository`** | Интерфейсы Spring Data JPA со стандартными CRUD-методами и запросами для фильтрации и отчётов. | `FilmRepository`, `FilmSessionRepository`, `TicketRepository`, `UserRepository` и др. |
| **`service`** | **Бизнес-логика.** Каждый сервис состоит из интерфейса и реализации (`*ServiceImpl`), которая содержит проверки правил, транзакции (`@Transactional`) и работу с репозиториями. | `FilmService`, `SessionServiceImpl`, `TicketServiceImpl`, `ReportServiceImpl`, `Statistics` |
| **`controller`** | REST-контроллеры. Принимают запросы, передают их сервисам и возвращают результат в JSON. Содержат только HTTP-логику. | `FilmController`, `TicketController`, `ReportController` и др. |
| **`controller.dto`** | Входные запросы (Java `record`) с аннотациями валидации. Для создания и обновления используются отдельные классы. | `FilmCreateRequest`, `FilmUpdateRequest`, `SessionCreateRequest`, `BuyTicketRequest` и др. |
| **`controller`** (`ApiExceptionHandler`) | Глобальная обработка ошибок (`@RestControllerAdvice`): `NoSuchElementException` → 404; `IllegalArgumentException`, ошибки валидации и неверный JSON → 400; `IllegalStateException` и нарушение ограничений БД → 409. | `ApiExceptionHandler` |

Ответы API возвращают сущности модели в формате JSON, входные данные принимаются через DTO.

## REST API Документация

После запуска приложения интерактивная документация (Swagger UI) доступна по адресу:
**[http://localhost:8080/swagger-ui/index.html](http://localhost:8080/swagger-ui/index.html)**

### Основные эндпоинты:
| Ресурс | Методы | Описание |
| :--- | :--- | :--- |
| `/api/halls` | `GET`, `POST`, `GET /{code}`, `PUT /{code}`, `DELETE /{code}` | Управление кинозалами |
| `/api/genres` | `GET`, `POST`, `GET /{code}`, `PUT /{code}`, `DELETE /{code}` | Справочник жанров |
| `/api/films` | `GET ?title=&genreCode=`, `POST`, `GET /{code}`, `PUT /{code}`, `DELETE /{code}` | Каталог фильмов с фильтрами |
| `/api/sessions` | `GET ?hallCode=`, `POST`, `GET /{code}`, `PUT /{code}`, `DELETE /{code}` | Расписание сеансов (билеты генерируются при `POST`; `PUT` меняет только фильм и цену) |
| `/api/tickets` | `GET ?sessionCode=&status=&customerLogin=`, `GET /seat?sessionCode=&row=&seat=`, `GET /{number}`, `POST /{number}/purchase`, `DELETE /{number}` | Просмотр, покупка (в теле запроса передаётся `login` покупателя) и удаление свободных билетов |
| `/api/users` | `GET ?role=`, `POST`, `GET /{login}`, `PUT /{login}`, `DELETE /{login}` | Управление учётными записями (роль при обновлении не меняется) |
| `/api/reports` | `GET /sessions/{code}/revenue`, `GET /films/sold-tickets`, `GET /statistics` | Выручка сеанса, продажи по фильмам, общая статистика |

## Быстрый старт

### 1. Требования
* JDK 21
* Maven
* PostgreSQL 18

### 2. Настройка базы данных
1. Создайте базу данных с именем `cinema`.
2. Откройте **Query Tool** в PgAdmin и выполните скрипт: `db/schema.sql`.

### 3. Конфигурация
Параметры подключения заданы в `src/main/resources/application.properties`.

### 4. Запуск приложения
```bash
./mvnw clean spring-boot:run
```
